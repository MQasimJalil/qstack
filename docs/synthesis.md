# How qstack combines the upstream skills

These examples describe the executable pilot. The [full catalog](catalog.md) records every upstream disposition and the procedure that retains it. The upstream links identify the methods that informed each decision.

| Procedure | What the two stacks contribute | Combined behavior |
| --- | --- | --- |
| Plan | gstack reviews architecture, failure modes, and coverage together. pstack sketches genuinely different ownership shapes and asks what assumption safety depends on. gstack already adopted the two-shape idea. | One plan records the current boundary, the selected design, one reachable failure, and the check that proves the key behavior. Compare two shapes when ownership changes. [gstack plan review](https://github.com/garrytan/gstack/blob/5dcd76b4eae6/plan-eng-review/sections/review-sections.md.tmpl#L386) · [pstack architect](https://github.com/cursor/plugins/blob/bf0c7cd80abd/pstack/skills/architect/SKILL.md) · [pstack blast radius](https://github.com/cursor/plugins/blob/bf0c7cd80abd/pstack/skills/blast-radius/SKILL.md) |
| Model | gstack maps failure modes to evidence. pstack makes named transitions explicit, checks a bounded state space, and demands a broken control that fails the same invariant. | TLC checks the protected model and its deliberate fault control. The counterexample supplies the actions for the runtime check. [gstack failure-mode review](https://github.com/garrytan/gstack/blob/5dcd76b4eae6/plan-eng-review/sections/review-sections.md.tmpl#L557) · [pstack formal verification](https://github.com/cursor/plugins/blob/bf0c7cd80abd/pstack/skills/create-formal-verification-skill/SKILL.md) · [pstack statechart](https://github.com/cursor/plugins/blob/bf0c7cd80abd/pstack/skills/statechart/SKILL.md) |
| Review | gstack has a production-impact floor and accepts an empty findings list. pstack demands a real trigger and proof, and merges findings with the same root cause. | One review checks the frozen input and the evidence mapping. A blocking finding needs a location, a reachable failure, and an impact on the plan. [gstack review policy](https://github.com/garrytan/gstack/blob/5dcd76b4eae6/docs/review-policy.md#L11) · [pstack interrogate](https://github.com/cursor/plugins/blob/bf0c7cd80abd/pstack/skills/interrogate/SKILL.md) |
| Verify | gstack tracks the selected checks and ties the verdict to the input. pstack starts and drives the real app and verifies the observable outcome. | Bombadil drives one browser procedure on the protected app and the deliberate fault control. The report ties both observations to the TLC witness and the exact tested input. [gstack verify](https://github.com/garrytan/gstack/blob/5dcd76b4eae6/verify/SKILL.md#L157) · [pstack verification skill](https://github.com/cursor/plugins/blob/bf0c7cd80abd/pstack/skills/create-verification-skill/SKILL.md) |

The portable instructions use a request and reply contract for planning and review. Codex, Claude Code, a custom stdin/stdout command, and a chat agent with file access can all use that contract. Host instructions belong in installation and transport code. The checked model and the browser fixture run outside the agent's reply.
