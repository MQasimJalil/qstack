# Engineering Mode

## Procedure

1. Restate the outcome, name its done predicate, and choose one primary playbook. Record the state shape and smallest change when implementing. Track scope, verification, delegation, and unresolved bottlenecks. Route work beyond one session to a bespoke workflow or program as appropriate.
2. Route investigation to source flow or history according to the question. For a bug fix, reproduce on the matching surface, isolate the first wrong decision, repair it, and replay. For a feature, trace the subsystem, model its data, select design alternatives when warranted, build, review, and exercise the user path. For a refactor, freeze the behavior contract and prove equivalence after subtraction and reshaping.
3. Route a one-off performance problem through baseline capture, grounding, one measured fix, and remeasurement. For sustained optimization, define the metric, freeze a sensitivity-checked harness, and log one baseline and result for each hypothesis. For live forensics, capture at the affected surface and isolate the mechanism. For a supplied trace, parse its format and symbols, query it, and report the supported diagnosis. Keep diagnosis read-only unless a fix is requested.
4. Use a disposable prototype to decide a concrete interaction or empirical fork. For visual parity, pin the baseline captures and prove each intended state with the actual image-diff harness. For skill authoring, validate metadata, links, and a representative invocation. For evaluation, blind equivalent candidates, freeze a scoring rubric, and compare real outcomes. Reuse the corresponding installed skill where a route already supplies these checks.
5. Route PR babysitting to one merge frontier and its exact head, with read-only status or authorized repair chosen up front. For shipping, independently verify each PR, then land the authorized contiguous run bottom-up. For a multi-phase plan, return an auditable checklist with one acceptance gate per slice. Open or update a PR only when requested, with intent, exact evidence, and outstanding limits. For workspace cleanup, audit verified usage and recoverability before any authorized deletion.
6. Use autonomous mode for one task with a checkable exit condition, or program orchestration for independent work across many tasks. For autopilot, give each PR a single write owner and verify its reviewed head once. Merge only in an authorized full queue. In stack mode stop at verified handoff, stacking only real dependencies. For session pickup read the prior trail and resume its next unverified action. For an explicit pause, stop at a safe boundary and leave a durable resume note. Reuse confirmed evidence and report only verified outcomes.
