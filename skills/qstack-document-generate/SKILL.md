# Document Generate

## Procedure

1. Read the repository entry points, public interfaces, commands, configuration, tests, and existing docs. Map the requested topics to source evidence and list the material gaps.
2. Choose the reader and purpose. Use a tutorial for learning by doing, a how-to for completing a task, reference for lookup, or explanation for understanding. Split mixed pages and cross-link them.
3. Write instructions as direct commands with concrete prerequisites and expected results. Use consistent names and unambiguous conditions. For a PR description or commit, state the behavior change and give evidence a reviewer can use.
4. Verify examples, flags, signatures, links, and discoverability from the project index. Keep unverified behavior labeled and publish or commit only when that action is within scope.
