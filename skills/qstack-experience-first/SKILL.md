# Experience First

## Procedure

1. Identify the people who consume the work and the few tasks that matter most to them. Include developers and future maintainers when they use the interface.
2. Explain the user effect of each candidate. Prefer the smaller coherent experience when extra controls or features would make the core task worse.
3. Use a lightweight prototype when it can settle a consequential choice. Observe alignment, transitions, feedback, and error states on the core path.
4. Record the chosen tradeoff using the outcome the affected people will notice.
