# Plan DevEx Review

## Procedure

1. Identify the developer persona and the task that demonstrates the product's value. Inspect the relevant docs, CLI help, SDK examples, and proposed changes. Note any journey steps still hypothetical.
2. Trace discovery, install, first success, real use, debugging, and upgrade as a first-time developer. Count steps and estimate or measure time to first success with stated conditions.
3. Choose the requested depth among expansion, polish, and triage. Score usability, credibility, findability, access, value, desirability, and usefulness from cited touchpoints. Mark any unsupported dimension as unmeasured.
4. Look for recovery instructions, machine-readable error signals, and a concrete first success. Rank evidenced friction by its effect on adoption and record pre-implementation scores so the live audit can compare them.
