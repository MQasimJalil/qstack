# Office Hours

## Procedure

1. Read the project brief, existing product, and prior design decisions. Choose startup discovery for a venture or internal initiative and builder discovery for a hobby, research, or open-source project.
2. For startup discovery, ask only unresolved questions appropriate to the stage. Probe demand shown by behavior, the current workaround and its cost, a specific user and consequence, the smallest viable offering, surprising observations, and how the need may change. For an internal project, identify the demo and proof a sponsor would need.
3. For builder discovery, find the most interesting experience to prototype, who would use or share it, the nearest existing project, and the quickest useful first version. Carry concrete build steps forward.
4. Challenge the premise against the cost of doing nothing and the code already in place. Compare two or three approaches that differ in scope or mechanism, with likely value, effort, and the assumptions each depends on.
5. Write a design brief with evidence, target user or use case, constraints, choices considered, recommendation, and the open questions that could change it.
